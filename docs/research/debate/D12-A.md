# D12-A: Manim as first-class renderer (FOR)

## Thesis
Manim is the only option in the plan that renders algorithm, graph and math motion natively, deterministically and for free on CPU. Adopt it, sandboxed, behind a spike gate with HTML/SVG as the fallback.

## Arguments
1. **Licence and currency.** Manim is MIT, double-licensed (3blue1brown LLC and Community Developers). Version 0.22.0 was released 2026-10-08, with Python 3.11-3.14 classifiers. https://pypi.org/project/manim/ . The project is actively maintained.
2. **Windows install is light.** The official guide is `uv init` + `uv add manim`. The only noted extra is the Microsoft C++ Build Tools if the build asks for them. LaTeX can be skipped if you need no typeset formulas, so MiKTeX is needed only for Tex/MathTex-style formulas. https://docs.manim.community/en/stable/installation/uv.html . An optional `manim[typst]` extra exists (same page). Spike E still has to prove ffmpeg and Cairo on this PC (UNVERIFIED).
3. **Fits the GPU constraint.** Manim's default renderer is Cairo (CPU). The 4 GB GTX 1650 Ti rules out generative video (file 11, G9, section 2), while code-drawn animation avoids the VRAM issue. Render time is UNVERIFIED: my search found no benchmark, so Spike E must time it. For 1080p/30 pass `-r 1920,1080 --fps 30`, because the presets differ by version. https://flyingframes.readthedocs.io/en/v0.15.2/cheatsheet.html
4. **Ready-made authoring prompts.** Yusuke710/manim-skill is MIT. It is a SKILL.md for Claude Code/Codex that runs narration, TTS (Kokoro, the same as Task 8), code, render and mux. https://github.com/Yusuke710/manim-skill . Prompts can be vendored legally (file 11, section 2 says to vendor, not call at runtime).
5. **Directly closes G1/G2/G3.** Reveals can be scheduled from `words.json` cues. The render is deterministic and frame-inspectable (file 11, section 3). It is the "best fit for technical explainers" per file 11, section 2.

## Strongest opposing point and answer
Executing LLM-written Python is a security and reliability risk, and Windows lacks real sandboxing. Answer: the proposition already constrains it. An AST import allowlist, a subprocess with a timeout, and a run-folder-only cwd limit the realistic failure modes (a hang, a bad import). Hostile output is a prompt-injection path only through the research text. Treat the AST check as defence in depth, not a security boundary. It is a single-owner pipeline on its own machine with no untrusted users. Add a repair cap of 2 and a fallback to HTML or stock B-roll (file 11, section 3). Residual risk: allowlisted modules can still be abused, e.g. `open()` and `__import__` unless the AST check bans them (UNVERIFIED design detail).
